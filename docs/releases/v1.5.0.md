# BerryBrain 1.5.0 — vaults, supervised Ask plans, 1,576 agent skills & architecture integration

Product release targeting schema 25 (`/api/v1` backward-compatible).

## Highlights

- **First-class physical Vaults & sort controls**: Register named physical vaults (`vaults` table, `GET /api/v1/vault/namespaces`) inside the shared owner workspace, filter Notes, Graph, Home, Ask, Activity, and Monitor by vault (`All Vaults` or a specific namespace), preserve unassigned notes safely, and toggle Vault/Note sidebar sort order (`Recent` vs. `A–Z`).
- **1-Click Auto Config AI Setup**: Automatically probe Local (Ollama) or Cloud OpenAI-compatible provider catalogs, assign capability-verified Main, Embedding, Judge, and HippoRAG model slots, resolve Gemini/OpenAI-compatible rate-limit fallbacks cleanly, and display live step-by-step compatibility progress during validation.
- **1,576 standardized Markdown Agent Skills (`skills/`)**: Unified context-routed skill library (15 priority-1 BerryBrain core skills, 177 scientific skills, 1,100 scientific reference modules, 265 Fabric cognitive patterns, and 19 Anthropic workflow skills) inspectable via `GET /api/v1/ai/skills`. Skills enforce structural rigor while keeping canonical vault and admitted graph evidence authoritative (`[Title](bbref:<evidenceId>)`).
- **Typed Ask references & Supervised Ask Action Plans**: Reference `@note`, `@folder`, `@vault`, and `@node` directly in Ask with automatic disambiguation and `Focus in Graph`. Propose and approve supervised plans (`create_note`, `create_vault_and_note`, `enrich_note`) using full (`approve_full`) or step-by-step (`ask_for_approval`) human approval with exact Markdown preview, empty-vault rollback on cancellation, uncitable draft quarantine until explicit hash-verified review, and Editor Ask scoped line-level diff previews (`selected_block`, `current_section`, `entire_note`).
- **24h Enrich AI with verified web provenance**: Continuous 24-hour background enrichment (`RESEARCH_GRAPH`, `VALIDATE_GRAPH_NODE_WITH_WEB`, `ENRICH_GRAPH_NODE`) validates low-support or unresolved graph knowledge against external sources and attaches explicit epistemic stances (`source_supports`, `source_expands`, `source_contradicts`) without overwriting canonical user Markdown.
- **Interactive Markdown tasks & bounded personalization**: Toggle `- [ ]` / `- [x]` checkboxes directly in Preview and Split Mode with unsaved-buffer conflict protection, and configure optional bounded user profile preferences that never override source evidence.
- **External Architecture Integration Kit**: Added [`docs/integrating-berrybrain-architecture.md`](../integrating-berrybrain-architecture.md), zero-dependency Node.js/ESM client [`examples/berrybrain_client.mjs`](../../examples/berrybrain_client.mjs), upgraded Python client [`examples/berrybrain_client.py`](../../examples/berrybrain_client.py), and [`examples/README.md`](../../examples/README.md).

## Compatibility, migrations, and boundaries

- **Database schema 14 → 25**: Additive migrations 15–25 preserve all existing Markdown files, graph nodes/edges, observations, service-token digests, and job history. Create and verify a manifest-backed backup before upgrading; downgrading across schema versions requires restoring the matching backup rather than rolling back container images alone.
- **Workspace & security boundaries**: BerryBrain remains a single owner-managed shared workspace. Named vaults are physical organizational namespaces, not per-user or per-vault ACL isolation boundaries. Service Bearer tokens authenticate trusted backend callers (`POST /api/v1/notes`, `/search`, `/graph/infer`, `/graph/ontology/export`), cannot approve human Ask action plans, and must never be distributed in public browser bundles.
- **Epistemic contracts**: Evidence support (`evidence-support-mean-v2`) applies only to eligible derived artifacts (never raw canonical notes or vaults) and is not a calibrated probability of factual truth. Human feedback updates scoped, reversible policy (`model_weights_updated=false`).
