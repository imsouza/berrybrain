# BerryBrain 1.4.12 — lighter workspace reads

Product performance maintenance; no new TCC/research experiments.

## Changes

- Canvas reads use `GET /graph/edges?compact=true`, excluding evidence blobs and
  confidence factors while retaining topology, stable IDs, reasons and bounds.
  The default API projection remains complete for audit/external clients.
- Smaller edge pages, concurrent metadata loading and cancellation of abandoned
  requests reduce navigation work. Ontology shapes/colors and pinned-node
  behavior are preserved.
- Editor/graph/sidebar polling no longer overlaps or starts new reads in hidden
  tabs. Editor/graph progress refreshes at least 15 seconds after completion,
  rather than every 5 seconds; this trades update frequency for lower load.
- Progress queries load only note identity and job state. Global maintenance
  cannot displace note-linked jobs from the latest-500 sample.
- Home avoids per-note legacy JSON joins and selects recent insight IDs before
  fetching large records. Assimilation queries only incident note edges.

## Evidence and limits

On a read-only snapshot comparison, 1,170 edges required 899,000 JSON bytes in
the compact projection versus 1,435,615 bytes previously (37.38% less), with
identical topology and graph version. Progress found 27 notes previously hidden
behind maintenance jobs. Timing samples improved but were not controlled
benchmarks: cache, fixed ordering and competing host work confound attribution.
Do not interpret them as guaranteed end-to-end latency or new paper results.

Local validation: 69 backend checks, 4 polling checks and 19 browser scenarios
passed; production build, lint and typecheck passed before the version-only
release bump. CI validates the final release candidate separately.

No data deletion, bulk retries, provider replacement or schema migration.
Back up before deployment and retain previous images/containers for rollback.
